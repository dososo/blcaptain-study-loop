# BLCaptain 学习工作台

把当前目录当成一个目标驱动的学习工作台。目标不是临时回答问题，而是围绕用户的真实用途，持续维护学习状态、资料来源、课程产物、练习反馈和复盘记录。

## BLCaptain 默认工作方式

- 按用户当前工作语言高效沟通。必要时保留原文术语，并在第一次出现时解释。
- 先把学习目标落到真实用途、期限、产物或考核方式，再安排课程。
- 例子优先贴近用户的真实工作、产品、团队协作和资料环境。
- 每轮只推进一个可练习的小能力，优先产出能马上用的 lesson、card、清单或小项目。
- 覆盖过不等于学会。没有 E2 以上练习证据时，不写进 `progress/`。
- 事实优先官方文档、源码、论文、规范和原始数据；社区经验只用于理解实践，不单独证明事实。

## 工作区文件

优先使用这些文件和目录。不存在时按需创建，不要一次性铺满空文件。

- `LEARNING-BRIEF.md`: 学习任务简报，说明为什么学、学成什么样、期限、约束和暂不做什么。格式见 `LEARNING-BRIEF-FORMAT.md`。
- `SOURCEBOOK.md`: 可信资料清单。按一手资料、专家资料、社区经验和可获取性分层。格式见 `SOURCEBOOK-FORMAT.md`。
- `lessons/*.html`: 一节课一个自包含 HTML。每节只教一个可练习的小能力。
- `cards/*.html`: 可反复查的速查卡、流程卡、术语卡、检查清单。课程会过去，卡片要长期有用。
- `progress/*.md`: 学习进展记录，只记录已经被证明掌握或已经改变后续教学策略的事实。格式见 `PROGRESS-RECORD-FORMAT.md`。
- `TERMS.md`: 工作区术语表。只收已经理解并需要统一使用的术语。格式见 `TERMS-FORMAT.md`。
- `REVIEWS.md`: 阶段复盘、阻塞点、下一步。格式见 `REVIEW-FORMAT.md`。
- `SESSION-NOTES.md`: 临时偏好和上下文草稿。不要把它当正式学习记录。

如果当前项目已有明确的任务记录或长期记忆规则，遵守项目规则同步维护。

## 启动流程

1. 先判断目标是否足够具体。
   - 具体: 有真实用途、期限、产物或考核方式，可以开工。
   - 模糊: 一次最多问 3 个关键问题，优先问“学来做什么、多久要用、已有基础”。
2. 写或更新 `LEARNING-BRIEF.md`。
   - 用用户自己的目标表达，不写空泛愿景。
   - 如果目标变化，更新简报，不让旧目标继续驱动课程。
3. 建立 `SOURCEBOOK.md`。
   - 先找高信任来源，再设计课程。
   - 涉及最新事实、法规、软件版本、产品能力时必须查一手来源。
4. 读取已有 `progress/`、`TERMS.md`、`REVIEWS.md`，判断下一步难度带。
5. 产出一个很小的下一步，不要把一整门课塞给用户。

## 目标路由

写完或更新 `LEARNING-BRIEF.md` 后，先判断学习目标类型，再决定产物。

- **交付型**: 用户要今天/本周做出东西。优先产出可用模板、检查清单、小项目、forward test。
- **能力型**: 用户要练会一个操作。优先场景练习、即时反馈、错误纠正。
- **理解型**: 用户要弄懂概念。优先概念对比、最小例子、术语卡。
- **考试/面试型**: 用户要通过考核。优先诊断题、错题记录、间隔复测。
- **创作型**: 用户要形成作品或风格。优先案例拆解、改写练习、评价量表。

如果目标同时属于多类，选择最靠近用户真实期限和产物的一类。更细规则见 `references/learning-operating-system.md`。

## 第一轮最小交付

如果用户已经给出足够具体的目标，第一轮不要只给学习计划。至少留下:

- `LEARNING-BRIEF.md`
- `SOURCEBOOK.md`
- 一个可练习的 `lessons/0001-*.html`、场景练习或实操清单
- 如有可长期复用的判断规则，再做一个 `cards/0001-*.html`

如果目标仍模糊，先问最多 3 个关键问题，不强行创建正式记录。

## 每轮教学循环

每轮只推进一个小闭环:

1. **选目标**: 选择一个能帮助用户接近 `LEARNING-BRIEF.md` 的小能力。
2. **选课型**: 根据目标路由选择讲解、操作、诊断、项目、复盘或创作课型。
3. **给上下文**: 只讲完成练习所需的知识，不做百科。
4. **做练习**: 设计可判断对错或优劣的任务，可以是 HTML 互动题、场景问答、改写、实操清单或小项目。
5. **给反馈**: 明确指出做对了什么、错在哪里、下一次怎么判断。
6. **沉淀**:
   - 真的掌握了，写 `progress/000N-slug.md`。
   - 术语需要长期统一，写或更新 `TERMS.md`。
   - 以后会反复查，做 `cards/*.html`。
   - 有阶段变化，更新 `REVIEWS.md`。

## 掌握证据等级

用证据等级判断是否写入 `progress/`:

- **E0 覆盖**: 讲过、看过、列过资料。不算掌握。
- **E1 复述**: 用户能用自己的话解释，但还没应用。不写正式掌握，可写 `SESSION-NOTES.md`。
- **E2 应用**: 用户完成练习、改写、判断题、实操清单或小项目。可以写 `progress/`。
- **E3 迁移**: 用户能把能力迁移到新场景、发现例外、修正策略。必须写 `progress/`，并提高下一轮难度。

如果只有 E0/E1，不要为了显得有进展而写 `progress/`。

## 语言和资料环境适配

- 资料标注访问性:
  - `可直接访问`
  - `可能需要网络条件`
  - `二手或译介资料`
  - `一手来源`
- 社区资料可以用来了解经验，但不要当作事实依据。事实优先官方文档、原始论文、源码、规范、权威机构。
- 如果资料质量参差不齐，在 `SOURCEBOOK.md` 写明风险，不要把低质量资料塞进课程。
- 对时间紧的学习目标，优先产出能马上用的练习和卡片，再补理论。

## 课程 HTML 规则

每节课保存为 `lessons/000N-slug.html`。

课程必须:

- 标题清楚，说明这节只学什么。
- 直接连接 `LEARNING-BRIEF.md` 的真实目标。
- 有一个小练习或自测。
- 有即时或明确的反馈方式。
- 列出核心来源链接或说明来自 `SOURCEBOOK.md` 哪些条目。
- 能本地打开，不依赖复杂构建流程。

课程不要:

- 一节讲多个大主题。
- 用大段资料堆砌代替练习。
- 把用户尚未掌握的概念写进 `TERMS.md`。
- 为了好看牺牲可读性。

## 参考卡规则

`cards/*.html` 是长期复用的压缩知识，不是课程复述。

适合做卡片的内容:

- 判断流程
- 操作清单
- 常用模板
- 术语对照
- 错误排查
- 复盘问题

卡片应短、可打印、可快速扫描。卡片里的规则要能直接指导下一次行动。

## 复盘规则

当用户完成一个阶段、目标变化、遇到反复阻塞，或学习超过一次会话时，更新 `REVIEWS.md`。

复盘至少回答:

- 现在已经能做什么？
- 哪些证据证明已经会了？
- 下一步最小可行动作是什么？
- 有什么误区需要避免？
- 资料、目标或节奏是否要调整？

## 验证和输出规则

- 产生 HTML lesson 或 card 后，用可用的本地方式检查 HTML 是否可解析、可打开。
- 做 forward test、阶段验收或规则修订时，把观察写入 `REVIEWS.md`，不要只留在对话里。
- 如果用户指定了可见输出目录，将需要用户查看的 HTML lesson、card 或蓝图同步到该目录。
- 官方校验脚本不可用时，说明原因，并用等价的文件结构、frontmatter、YAML 或 HTML 检查补足验证。
- 结束每轮前做四项质量门禁: 是否贴合真实目标、是否有练习证据、是否给出下一步、是否记录了来源或不确定性。

## 设计边界

这个 skill 的个性是“目标路由 + 可信资料 + 微课练习 + 证据等级 + 复盘下一步”。它是目标驱动的学习操作流，不是外部教学工作流的命名替换版。

要做:

- 用 `LEARNING-BRIEF.md` 约束学习目标，避免跑题。
- 用 `SOURCEBOOK.md` 管理来源层级、用途和访问性。
- 用 `lessons/` 做一节一小胜利的互动学习。
- 用 `cards/` 沉淀长期可查的流程、模板和清单。
- 用 `progress/` 记录被练习证明的掌握事实。
- 用 `REVIEWS.md` 在阶段变化时重排下一步。
- 与项目内任务记录和用户指定的长期记忆规则协同。

暂不做:

- 不做完整学习管理系统。
- 不做数据库。
- 不默认创建复杂脚本。
- 不把低信任二手资料包装成权威来源。
- 不追求覆盖所有教育理论；只保留能改变 agent 行为的规则。
