# BLCaptain 学习操作流

这个 reference 用于在目标复杂、学习周期较长、或需要开源前自查时细化决策。普通学习请求不需要完整读取。

## 目标路由细则

| 类型 | 用户常见说法 | 第一轮产物 | 下一轮判断 |
|---|---|---|---|
| 交付型 | 今天做出、这周上线、我要写一个 | 简报、资料清单、最小产物、forward test | 产物是否能被真实使用 |
| 能力型 | 教我怎么做、带我练、我想掌握 | 场景练习、即时反馈、错误清单 | 用户是否能独立完成同类任务 |
| 理解型 | 我想搞懂、为什么、原理 | 概念对比、术语卡、最小例子 | 用户能否解释边界和反例 |
| 考试/面试型 | 准备考试、面试、考核 | 诊断题、错题表、复测计划 | 错题是否减少，解释是否稳定 |
| 创作型 | 想形成风格、写作品、做设计 | 案例拆解、改写练习、评价量表 | 用户是否能做出可评价作品 |

路由原则:

- 期限越近，越偏交付型。
- 用户有明确作品，优先做产物和评价量表。
- 用户只有好奇心，先做理解型，但必须尽快转成练习。
- 目标类型变化时，更新 `LEARNING-BRIEF.md` 和 `REVIEWS.md`。

## 课型选择

### 讲解课

适合概念陌生时。必须包含一个最小例子和一个自测问题。

### 操作课

适合工具、流程、写作、设计、代码、提示词。必须有可检查的输出。

### 诊断课

适合考试、面试、debug、能力摸底。先测再讲，不要先塞知识。

### 项目课

适合交付型目标。每轮都要让真实产物更接近可用，而不是只增加理解。

### 复盘课

适合连续学习、目标变化或反复卡住。必须更新下一步最小动作。

### 创作课

适合作品、风格和审美判断。必须给评价量表，不只给“好看/不好看”的口头反馈。

## 证据等级

| 等级 | 含义 | 是否写入 `progress/` |
|---|---|---|
| E0 覆盖 | 讲过、看过、列过资料 | 否 |
| E1 复述 | 用户能解释，但未应用 | 否，可写 `SESSION-NOTES.md` |
| E2 应用 | 用户完成练习、判断、改写或小项目 | 是 |
| E3 迁移 | 用户能迁移到新场景、发现例外、修正策略 | 是，并提高难度 |

不要把“我懂了”当 E2。E2 至少要有一个可观察行为或产物。

## 资料可信度

- S1 一手来源: 官方文档、源码、论文、标准、原始数据。
- S2 专家来源: 高质量教程、领域专家、经典教材。
- S3 社区经验: 论坛、帖子、实战复盘，只能辅助理解。
- S4 模型推断: 只能作为假设，不能当事实。

涉及新版本、法规、价格、平台规则时，必须记录最近检查日期。

## 开源差异化检查

开源前检查:

- 名称、文件结构、默认产物是否有独立产品语义。
- 是否能说明它解决的是学习执行问题，而不是某个外部 skill 的翻译问题。
- 是否有公开用户能理解的质量门禁。
- 是否有官方校验结果。
- 是否没有上游特有措辞、字段或文件名残留。

如果公开文档需要致谢，可以写“受状态化学习工作区理念启发”，但不要把 README 或说明写成对某个项目的逐项翻译。
