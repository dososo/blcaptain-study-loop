# 能把 Rust 错误处理转成 CLI 用户体验

## 已掌握

学习者能把 `Result`、错误类型和退出码用于真实 CLI 场景，让团队成员看到可理解的失败原因和下一步动作。

## 证据等级

E2 应用。

## 证据

已设计 4 类错误处理规则:

| 场景 | CLI 行为 | 用户看到什么 |
|---|---|---|
| 输入文件不存在 | 退出码 2 | 显示路径、原因、检查建议 |
| 输入格式错误 | 退出码 3 | 显示行号或字段名，给修复例子 |
| 输出路径不可写 | 退出码 4 | 提醒权限或目录不存在 |
| 内部未知错误 | 退出码 1 | 给简短说明，不暴露 panic 堆栈 |

已把发布前验收改成:

- `--help` 可以独立解释工具。
- README 里有 3 个真实命令例子。
- 团队成员按 README 能完成一次成功路径。
- 至少 2 个失败路径有可读错误提示。

## 为什么这算 E2

学习者不是复述 Rust 错误处理概念，而是将错误处理用于 CLI 的可用性设计，并形成发布验收标准。

## 下一步影响

- 下一轮可以写 `thiserror` 或自定义错误类型。
- 测试应覆盖 stdout、stderr 和退出码，而不仅是函数返回值。
