团队内部 CLI 发布检查卡

这张卡用于判断一个 Rust CLI 是否已经从“我机器上能跑”进入“团队可以试用”。不满足这些条件时，不要把 progress 写成 E3。

安装

  • 是否说明支持系统和 shell？
  • 是否提供一种最小安装方式？
  • 是否能在干净目录运行？

帮助

  • --help 是否说明用途？
  • 每个参数是否有默认值或约束？
  • 是否包含真实命令例子？

样例

  • 是否有成功输入样例？
  • 是否有失败输入样例？
  • 输出是否可 diff？

测试

  • 帮助文案 smoke test。
  • 成功路径 smoke test。
  • 至少 2 个失败路径测试。

风险

  • 路径、权限、编码和换行。
  • 同事的输入文件不干净。
  • 错误提示只有作者看得懂。

通过标准

  • 2 个团队成员独立跑通。
  • 失败时不用问作者也知道下一步。
  • README 可以直接复制命令。

最终一句话

内部 CLI 的发布标准不是“功能写完”，而是“目标用户能独立安装、运行、理解错误、完成一次真实任务”。
