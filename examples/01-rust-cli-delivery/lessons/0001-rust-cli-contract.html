BLCaptain Study Loop · Delivery Route

别先学完整 Rust，先设计一个能交付的 CLI 契约

本节只练一个能力：把“两周学 Rust”转成团队内部 CLI 的命令、输入、输出、失败场景和验收标准。

E2 目标 交付型 第一轮

完成后应该能写出一个可讨论、可实现、可验收的命令契约，而不是只有学习路线。

普通对话会怎么走

大概率给你 Rust 学习路线：所有权、借用、生命周期、trait、异步、项目实战。

问题是：两周后团队还是没有工具可用。

这个 skill 怎么改写

先问真实用途：谁用、处理什么、成功输出是什么、失败时怎么提示。

学习路径由交付物倒推，而不是由知识目录倒推。

第一轮只交付什么

一个 CLI 契约草案、一个 `--help` 轮廓、一个 thin slice 命令。

Rust 语法只学足够完成这三件事的部分。

命令契约模板

先写命令，不急着写实现。一个内部 CLI 最少要让同事看懂这四块。

bltool process <input-path> --out <output-path> --format json
bltool check <input-path> --strict
bltool explain <error-code>
字段要回答的问题验收方式
动词用户到底要做什么动作？团队成员能否猜出用途
输入路径、文件、目录还是 stdin？能否用真实样例跑通
输出写文件、打印文本还是返回 JSON？输出是否能被下游使用
失败用户最可能错在哪里？错误提示是否给出修复动作
